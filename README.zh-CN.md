**一个 HTML 文件，用你机器上现成的浏览器，在成堆的日志里找关键词。**

不用安装、不用起服务、不上传、不需要管理员权限。双击文件 → 选目录 → 输关键词 → 看结果。

## 快速开始

1. **下载 `logneedle.html`** —— 只有一个文件，约 68 KB。在 GitHub 上打开该文件，点 *Download raw file*。
2. **双击打开。** 它会在默认浏览器里打开。安装到此结束。
3. **点「选择日志目录」**，选中放日志的文件夹；也可以直接把文件夹拖到页面上。
4. **输入关键词，回车。**
5. 结果在下方按每个文件一块展示，命中处高亮，行号固定在左侧。
6. **点「清空」**，接着输下一个关键词。目录保持加载、已解析的文件仍在缓存里，所以第二次搜索不会再碰磁盘。

Edge / Chrome 的体验最好（拿到的是真正的目录句柄）。Firefox / Safari 走系统文件夹选择框，也就是旁边那个 **「旧版本浏览器下选择」** 按钮。

不需要别的东西：不用 Python、不用 Node、不用 npm、不装扩展、不会弹提权。

## 为什么做这个

- **你没有任何安装权限。** 生产机、跳板机、被锁死的 VDI 镜像上往往只有浏览器。`ripgrep`、`lnav`、`klogg` 都需要你装不上的东西。
- **日志是机密的。** 全部计算都在标签页里完成：不上传、无埋点、不引 CDN、不拉字体。打开开发者工具的 Network 面板就能确认。
- **日志是 GBK 的。** 国内 Windows 服务至今还在写 GBK/GB18030 日志，多数工具打开就是乱码。LogNeedle 逐文件识别编码，猜错了可以手动指定。
- **只有浏览器可用。** 隔离网、Citrix 会话、只能打开本地 HTML 却跑不了安装包的机器。
- **你想把工具丢给同事。** 就一个文件：聊天窗口发过去、放共享盘、贴进工单，照样能用。

## 功能一览

| 方面 | 具体能力 |
|---|---|
| 取目录 | 目录选择 API（Chromium）、系统文件夹选择框（所有浏览器）、把文件夹或零散文件拖到页面上 |
| 结果展示 | 每个文件一块可折叠卡片：相对路径、命中行数、识别出的编码、固定行号、高亮命中 |
| 折行 | 自动 / 始终换行 / 不换行。自动模式按每块的实际溢出宽度决定，只在必须折的时候折；窗口缩放、展开折叠都会重算 |
| 匹配 | 字面量或正则、区分大小写开关、多关键词 OR（空格或 `\|` 分隔）、0–10 行上下文 |
| 过滤 | 子目录过滤（如 `2024-05`）、文件通配（`*.log;*.txt`），并自动跳过 `.git`、`node_modules`、`$RECYCLE.BIN`、`$WinREAgent`、`System Volume Information`、`Recovery`、`__pycache__`、`.svn`、`.hg`、`.idea`、`.vscode`、`venv`、`.venv` |
| 编码 | UTF-8（含 BOM）、UTF-16LE/BE（含 BOM；无 BOM 时按字节分布嗅探）、GBK/GB18030、Big5 —— 逐文件判定，可手动覆盖 |
| 大目录 | ≤ 8 MB 的文件整读并进 LRU 文本缓存（预算 192 MB）；更大的文件按 1 MB 分块流式解码；二进制文件自动跳过；长扫描可点「停止」 |
| 上限保护 | 每文件最多行（默认 200）与总计最多行（默认 5000），可调；触顶会明确标注，而不是悄悄截断 |
| 输出 | 复制单块、复制全部、导出 TXT（UTF-8 带 BOM，记事本/Excel 直接打开）或 JSON |
| 自检 | 页面内「自检」按钮跑 29 项断言，含 GBK 字节夹具与流式解码边界 |
| 隐私 | 零网络请求、只读访问目录、不往你的日志里写任何东西 |

## 与其他工具对比

| | ripgrep | `grep` + `less` | klogg | lnav | **LogNeedle** |
|---|---|---|---|---|---|
| 需要安装 | 是（一个二进制） | 否 | 是（桌面程序） | 是 | **否 —— 一个 HTML 文件** |
| 界面 | 终端 | 终端 | 桌面 GUI | 终端 UI | **你的浏览器** |
| 按文件分组与高亮 | 纯文本匹配 | 纯文本匹配 | 有 | 有 | **有** |
| 无安装权限时可用 | 常常被挡 | 可以 | 基本不行 | 基本不行 | **可以** |
| 逐文件编码识别（GBK、UTF-16） | 无 | 无 | 部分 | 部分 | **有** |
| 实时跟踪（`tail -f`） | 无 | 有（`less +F`） | 有 | 有 | **无** |
| 超大目录的速度 | 极快 | 极快 | 快 | 快 | **几千个文件够用；比 `rg` 慢** |
| 能当一个文件发给同事 | 否 | 否 | 否 | 否 | **能** |

如果你有权限装 ripgrep，那就装 ripgrep：它更快、可脚本化，上表里几乎所有项都更强。LogNeedle 只解决 `rg` 覆盖不到的两件事——**你没有任何安装权限的机器**，以及**在终端里会变乱码的日志编码**。

## 它不是什么

- **不是日志采集/聚合平台。** 不往任何地方发送、后台不建索引、没有服务端、没有账号。
- **不是 `tail -f`。** 没有实时跟踪与文件监听，日志长了要再查一次。实时跟踪请用 `less +F`、`lnav` 或 `Get-Content -Wait`。
- **不是为几 GB 的单文件设计的。** 大文件确实会流式读，但瓶颈在浏览器标签页而不是工具本身；单文件很大时扫描会慢、页面会沉。
- **不做脱敏。** 命中行原样展示。它不上传任何东西，但也不打码——请像对待日志文件本身一样对待屏幕。
- **不支持压缩日志。** `.gz` / `.zip` 里的内容不会被解开，请先解压。
- **不支持输入绝对路径**，这是设计使然，见下面的常见问题。
- **不是编辑器。** LogNeedle 绝不会写入、重命名或删除你选中的目录里的任何东西。

## 编码支持

| 编码 | 识别方式 | 说明 |
|---|---|---|
| UTF-8（无 BOM） | 自动 | 严格校验，默认路径 |
| UTF-8（带 BOM） | 自动 | 匹配前剥离 BOM，首行和其他行一样能命中 |
| UTF-16LE / UTF-16BE（带 BOM） | 自动 | |
| UTF-16（无 BOM） | 自动（启发式） | 按 NUL 字节落在奇数位还是偶数位判断；不常见但确实存在 |
| GBK / GB18030 | 自动（回落） | GB18030 是 GBK/GB2312 的超集，一个标签都覆盖 |
| Big5 | 建议手动指定 | 繁体中文。由于 GB18030 几乎能解码任意字节序列，Big5 文件可能被猜成 GB18030；发现文字不对就在「编码」里选 Big5 |
| Shift_JIS、EUC-KR、Windows-1252 | 手动 | 与其他编码并列；浏览器不支持的标签会在下拉里标注出来 |

「编码」下拉可选：自动检测、UTF-8、GBK、GB18030、Big5、Shift_JIS、EUC-KR、UTF-16LE、UTF-16BE、Windows-1252。

## 常见问题

**为什么不能输入 `D:\logs` 这样的路径？**
因为网页不能按路径读磁盘——这是浏览器的安全模型，本地 `file://` 页面也不例外。所以 LogNeedle 是向浏览器**要**一个目录（选择框或拖拽），之后只能看到这个目录里的内容，且只显示相对路径。好处正是这个工具存在的理由：不用安装、不起服务、不要权限。需要按路径遍历文件系统，请用原生工具。

**日志显示乱码怎么办？**
打开「选项 → 编码」，把「自动检测」改成 **GBK**（或 GB18030）。繁体文件一般是 Big5。每块卡片的头部会显示该文件实际使用的编码，可以逐个文件核对。

**它会把我的日志发到哪儿去吗？**
不会。页面完全不发网络请求：没有脚本、字体、图片、埋点、错误上报。打开开发者工具 → Network，刷新，列表始终为空。只要文件里出现 `http(s)://` 引用或任何外部资源，`tools/check.mjs` 就会让 CI 失败。本地只存了两样东西：最近 10 次搜索记录和折行偏好，都在 `localStorage` 里，点「清除历史」即可清掉。

**能实时跟踪日志吗？**
不能。没有 `tail -f`、没有文件监听、不会自动刷新；目录只在你点「提取」时读取。实时跟踪请用 `less +F`、`lnav` 或 `Get-Content -Wait`。

**Firefox / Safari 能用吗？**
能，走系统文件夹选择框（**旧版本浏览器下选择**），拖拽也可以。代价是没有目录选择 API 那条路径：这个选择框会把整棵目录树先枚举完再返回，所以目录特别大时，打开会明显更慢。

**能扛多大的目录？**
舒服的区间是**几千个文件、几百 MB**。≤ 8 MB 的文件进内存缓存（预算 192 MB），更大的按 1 MB 分块流式解码，所以工具自身的内存是受控的——但渲染成千上万块结果卡片、以及持有大缓存，仍然是浏览器的负担。扫描拖太久可以调低「每文件最多行 / 总计最多行」、用「子目录过滤」或「文件通配」缩小范围，或者点「停止」后换个更精确的关键词。

**为什么有些结果标着「已达到上限」？**
因为撞到了每文件或总计行数上限（默认 200 / 5000）。这是刻意的：关键词命中半个目录时，它保证页面不卡死。在「选项」里调高上限，或者把关键词收窄。

**界面只有中文？**
目前是的。英文等其它语言是 Roadmap 第一项，而且界面文案是自包含的、没有框架挡路，所以翻译 PR 的工作量确实很小。见 [CONTRIBUTING.md](CONTRIBUTING.md)。

**它会改我的文件吗？**
不会。申请目录权限时就是只读（`mode: 'read'`），代码里也没有任何写入所选目录的路径。唯一会离开页面的文件，是你主动点的那两个导出（TXT / JSON），走浏览器正常的下载流程。

## 隐私

离开你机器的数据：没有。

- 产品文件里不存在 `http://` / `https://` 链接，没有 `<link>`、`<script src>`、`@import`、`url(...)`。CI 每次推送都用 `grep` 把这条钉死——见 [`.github/workflows/ci.yml`](.github/workflows/ci.yml)。
- 代码里没有 `fetch`、`XMLHttpRequest`、`WebSocket` 调用。
- 目录权限以 `mode: 'read'` 申请，随时可以在浏览器的站点设置里撤销。
- `localStorage` 只存最近 10 条搜索与折行偏好，别的不落盘。
- 用在线演示时，页面本身当然要走一次 HTTPS 下载（这就是 Web 的工作方式）；加载完之后，它的行为和本地文件完全一样，依然什么都不发。

自己验证：打开开发者工具 → Network，清空面板，跑一次搜索，看它一直是空的。或者运行 `node tools/check.mjs logneedle.html` 读「零外链」那几条断言，或者直接：

```bash
grep -nE 'https?://|fetch\(|XMLHttpRequest|new Worker' logneedle.html   # 什么都不输出
```

## 开发与测试

```bash
git clone https://github.com/dryQAQ/LogNeedle.git
cd logneedle

node tools/check.mjs logneedle.html   # 静态 + 核心逻辑校验，零依赖
pwsh -File tools/screenshot.ps1       # headless Edge/Chrome 端到端，并生成截图
node tools/screenshot.mjs             # 同一套端到端，跨平台版本
```

- **`tools/check.mjs`**：从 `logneedle.html` 里抽出两段 `<script>`，做语法检查，跑与页面内「自检」按钮**完全相同**的 29 项用例，校验 DOM id 契约（每个 `$('id')` 都有对应元素），断言没有混入外链或禁用 API，并测一遍匹配吞吐。CI 跑的就是它。
- **`tools/screenshot.ps1`**：用 CDP 驱动真实 headless 浏览器——从 `file://` 加载页面、选中 `examples/sample-logs/`、输入关键词、点「提取」，然后校验渲染、GBK 解码、三态折行、「清空」后再次搜索、页面内自检、控制台无报错，并写出 `docs/screenshot.png` 与 `docs/screenshot-gbk.png`。**已在 Windows 上验证。**
- **`tools/screenshot.mjs`**：同样的流程，不需要 PowerShell（用 Node 内置 WebSocket）。**本机未验证**——它存在是为了让这套检查也能跑在 Linux/macOS 的机器上；在有人跑通之前，请当作尽力而为。
- **`tools/mkdemo.py`**：需要重建演示数据时，用它重新生成 `examples/sample-logs/`（Python 3，可选——仓库里其它东西都不依赖 Python）。
- **`examples/sample-logs/`** 是演示数据：一个 UTF-8 服务日志、一个 GBK 中文日志、一个含超长行的 JSONL、一个子目录、一个二进制文件（用来验证二进制跳过）、一个不含命中的纯文本。里面 `README.txt` 列了值得一试的关键词：`ERROR`、`timeout`、`错误`、`payment` 等。

本次发布所用机器上的实测记录（Windows，Node 24.19.0）：

| 检查 | 结果 |
|---|---|
| `node tools/check.mjs logneedle.html` | **71 / 71 项断言通过** |
| 页面内「自检」（同一套用例，在浏览器里） | **29 / 29 项通过** |
| 匹配吞吐：20 万行合成日志，内存中约 14.4 MB（UTF-16），仅匹配环节（不含读盘与解码） | 多次运行 **88–141 ms，约 140–190 MB/s** |
| `tools/screenshot.ps1`：headless Edge 154 + CDP，19 项检查（加载、选目录、GBK 解码、三态折行、清空后重查、页面内自检、控制台） | **实测 19 / 19 通过**；这是最依赖具体环境的一环，请在你机器上重跑 |
| 端到端执行期间的控制台报错 | 无 |

数字会随环境变化：吞吐取决于 CPU，也取决于有多少工作花在解码而不是匹配上。

## Roadmap

1. **英文界面**（以及其它语言）。文案自包含、没有框架挡路，这是当前价值最高的贡献方向。
2. 键盘优先的导航：在结果块之间跳转、上一个/下一个命中。
3. 在目录选择 API 允许的前提下记住上次的目录，刷新后不必从零开始。
4. 面向结构化日志（JSONL）的字段筛选——一个轻量、离线的选择器，不是查询语言。
5. 明确不做：往你的日志目录里写东西。LogNeedle 保持只读。
